# タグの読み方

## 扱うこと

タグを記録する・数えるとき、2つの形式と終了時刻の有無をどう読み、重複をどう除くか

## 答え方と理由

### 0. 判断全体

`tag_type_code` の各コード（`tag_sleep_alcohol` など）が何を指すかは、この判断では答えない（Ouraのアプリの表示と突き合わせて確かめる）。

### 1. タグは2つのエンドポイントから取る

タグは、`enhanced_tag`（新）と `tag`（旧）の2つのエンドポイントから取る。項目が違う。

| | `enhanced_tag` | `tag`（旧） |
|---|---|---|
| 日付 | `start_day` | `day` |
| 開始 | `start_time` | `timestamp` |
| 終了 | `end_time`（期間タグだけ） | 無し |
| 種別 | `tag_type_code`（1つ） | `tags`（配列） |
| 内容 | `comment` か `custom_name` | `text` |

1. 記録なし

### 2. 終了が空なのを、欠測と読まない

終了が空なのは欠測ではない。体調の症状のような瞬間タグでは `end_time` が `null` で、運動・飲酒・昼寝のような期間タグにだけ入る。終了の有無で、瞬間か期間かを読む。終了が空の行を、欠測として扱わない。

1. （知見）実データで、大半の行が `end_time` を持たなかった。（出典：なし）

### 3. 数えるときは、2つの形式の重複を除く

同じタグが、2つの形式で二重に返ることがある。数えるときは（日付・種別・開始時刻）で重複を除く。重複のうち、終了を持つ `enhanced_tag` 側を採る。

1. （根拠）重複を除かないと、飲酒・運動などが二重に数えられる。（決定日：記録なし）

### 4. 記録するときは、両方の形式を残してよい

記録するときは、両方の形式をそのまま残してよい。重複を除くのは読む側。どちらの形式かを記録に残し、読む側が見分けられるようにする。

1. 記録なし
